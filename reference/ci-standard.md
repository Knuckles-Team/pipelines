# CI standard (shared pieces)

Pipelines owns the reusable parts of the fleet CI standard; each repository calls them at `@main`. The checks they run are the [gate standard](gate-standard.md).

- `gates_pipeline.yml`: one `gates` job. Pull requests run the caller's pre-commit file at the commit stage and the pre-push stage over `--from-ref/--to-ref`; a main push sets `all-files: true`. Then the affected-test subset from `pr-test-scope`. Inputs: `config`, `ci-config`, `test-scope`, `src-root`, `runner`, `rust`, `all-files`, `extra-manual-hooks`, `skip-hooks`, `setup-command`, `docs-only-paths`, `timeout-minutes`. Every input has a default. On `push` events the workflow adds `spec-trailers` to `SKIP`: trailers are a property of pull request commits and a squash merge does not carry them; pull request runs always enforce the hook.
- `gates_pipeline.yml` skips the pre-push `tests-fast` hook (and the deprecated `fast-tests` id) when `test-scope` is set, because its affected-test step runs the same subset without the local cap.
- `connector_pr_pipeline.yml` (PIPE-RELEASE-R011): the connector pull request workflow. It wraps `gates_pipeline.yml` with `config: .pre-commit-config.yaml`, `stages: pre-commit` and a 10-minute cap, then runs the affected unit tests. It never publishes. Input `sync-args` (default `--all-extras --all-groups`) sets the `uv sync --frozen` arguments for a connector whose extras cannot all build on a CPU runner. A connector adds a caller on `pull_request`.
- `container_pipeline.yml` ends with a verification step (PIPE-RELEASE-R012). A connector release publishes the PyPI version and the `<version>-mcp` image, and the run fails when either is missing. The `release-standard` hook (PIPE-RELEASE-R013) warns when a connector lacks `docker/Dockerfile` or an enabled `container_pipeline.yml` job.
- `main_pipeline.yml`: the main and release-tag workflow. Job `tests` runs the full suite; job `supply-chain` runs one dependency audit (`pip-audit` over the runtime lock, or `cargo deny check advisories` with `rust: true`). Inputs: `test-scope`, `runner`, `rust`, `setup-command`, `timeout-minutes`. It never publishes; release workflows stay with each repository.
- `advisory_pipeline.yml`: the weekly advisory workflow. It runs the advisory `pipelines-hook` gates, codespell, vulture, bandit and any `extra-commands`, writes one Markdown report to the job summary and the `advisory-report` artifact, and never fails. Inputs: `gates`, `python-tools`, `extra-commands`, `scanners`, `runner`.
- Concurrency belongs to the caller: PR group `pr-<workflow>-<number>` and main group `main-<workflow>` cancel superseded runs; release and pages groups never cancel. The workflow header carries the copyable block.
- Input `docs-only-paths` (default empty): space-separated bash patterns of docs and spec paths. When every file in a pull request diff matches one, the job passes right after checkout. A caller that sets it drops `paths-ignore` from `pull_request` and has no skip companion, so exactly one `gates / gates` check exists. A skip run under the same name can then never mask a failing real run on a mixed code and docs pull request.
- `templates/workflows/gates-skip.yml`: the older companion that reports the required `gates` check for docs/spec-only changes that `paths-ignore` skips. On a mixed pull request both workflows report the same name; prefer `docs-only-paths`.
- `python_pipeline.yml` input `require-tag` (default `false`): when `true` the job fails before building unless the ref is a `v*` tag. A release workflow triggered by `push: tags: ['v*']` sets it.
- Hook `fast-tests` (pre-push): affected tests only, 120 s cap, base from `PRE_COMMIT_FROM_REF`.
- Local hooks follow the [pre-commit standard](precommit-standard.md): only fast checks at pre-commit and pre-push. The CI-only gates are in `.config/ci-gates.yaml`, and the `ci-config` input of `gates_pipeline.yml` runs them.

## Required status check

A repository that adopts `gates_pipeline.yml` through a caller job named `gates` requires the single status check `gates / gates` in its branch ruleset. The docs and spec-only skip companion reports the same name.

## Agent contract

Every repository gives a cold agent the same setup and the same orientation (PIPE-CONNSPEC-R175 to R177):

- `scripts/bootstrap.sh` is idempotent and non-interactive. It installs a current uv (via `pip install --user`, never a piped network installer: SC-INSTALL-001), the Python pinned in `.python-version` (default 3.14), runs `uv sync --locked` (plain `uv sync` until the repository has a `uv.lock`), installs the pre-commit and pre-push hooks, and prints the gate command. A repository with extra setup (sibling pins, native builds) extends the script and keeps these steps.
- `AGENTS.md` carries the block between `<!-- agent-contract:start -->` and `<!-- agent-contract:end -->`. The block states the **Owner boundary** (with a link to [ecosystem boundaries](ecosystem-boundaries.md)), **Setup** (`scripts/bootstrap.sh`), **Gates** (`uvx pre-commit run --all-files`), **Commits** (Spec trailer, assisting-agent `Co-Authored-By:` trailer, explicit staging, own Git identity) and a link to the [organization AGENTS.md](https://github.com/Knuckles-Team/.github/blob/main/AGENTS.md). The text is tool-neutral. Content outside the markers belongs to the repository. `CLAUDE.md`, where present, only imports `@AGENTS.md`.
- The pre-push hook `agent-contract` flags a missing `scripts/bootstrap.sh` or one that trips SC-INSTALL-001/002, a missing `AGENTS.md`, or a missing or incomplete block. It warns (exit 0) until the fleet has converged; `--strict` blocks.
