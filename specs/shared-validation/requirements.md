# PIPE-VALIDATION requirements

| ID | Requirement | Acceptance |
|---|---|---|
| `PIPE-VALIDATION-R001` | **Bounded shared repository validation.** The validation package runs declared offline checks with structured required and advisory outcomes. | The child requirements below cover the command. |
| `PIPE-VALIDATION-R001.1` | **Strict policy.** `validation/policy.py` rejects unknown keys, duplicate IDs or gates, unsupported gates, missing acceptance mappings, and invalid deadlines before dispatch. | `test_policy_refuses_ambiguous_checks` and `test_policy_accepts_repository_group`. |
| `PIPE-VALIDATION-R001.2` | **Passive events do no work.** `validation/cli.py` returns an explicit inactive result for post-merge, post-checkout, and post-rewrite without loading policy or dispatching checks. | `test_passive_git_event_does_not_dispatch` uses disposable Git repositories and sentinel tools. |
| `PIPE-VALIDATION-R001.3` | **Required checks fail closed.** `validation/runner.py` reports missing prerequisites separately; required failures, unavailable results, and timeouts block. Advisory outcomes remain visible. | `test_required_and_advisory_outcomes` and `test_missing_git_is_unavailable`. |
| `PIPE-VALIDATION-R001.4` | **Bounded execution.** `validation/runner.py` enforces check and run deadlines, terminates its process group, and records measured duration. SIGTERM and SIGINT clean up worker descendants while preserving the runner signal exit; prior signal policies are restored. | `test_deadline_terminates_child_process`, `test_run_budget_marks_remaining_checks`, and `test_runner_signal_cleans_worker_group_and_keeps_signal_exit`. |
| `PIPE-VALIDATION-R001.5` | **Actionable evidence.** `validation/cli.py` prints grouped concise results and writes a versioned report with check logs, remedies, acceptance IDs, and elapsed time. Published and self-run pre-commit registrations expose advisory output even when the aggregate exit is zero. | `test_summary_matches_evidence` verifies clean and failed runs; `test_advisory_report_is_visible_through_pre_commit` covers advisory fail, unavailable, and timeout through actual pre-commit. |
| `PIPE-VALIDATION-R001.6` | **Retain AU ignore acceptance.** The shared gitignore checker retains all 16 AU patterns and rejects tracked build, dist, and target families without confusing ordinary source filenames. | `test_au_ignore_acceptance_is_retained` runs real disposable Git fixtures. |
| `PIPE-VALIDATION-R001.7` | **Standard repo files are provided, not copied.** The `connector-standard` hook runs `connector-files`, `connector-codespell`, `connector-security` and `connector-api-parity`. A tracked `scripts/security_sanitizer.py` (the shared `security-sanitizer` inside `secrets` replaces it), `.codespellignore`, `.bumpversion.cfg`, `docker/{Dockerfile,debug.Dockerfile,mcp.compose.yml,agent.compose.yml}`, `.security/{repository_fuzz.py,authenticated_negative.py}`, `.security/security-contract.json`, `scripts/bootstrap.sh`, `scripts/verify_api_integration.py`, `tests/test_verify_api_integration.py`, or the generated ontology files is a finding. | `tests/hooks/test_connector_central.py::test_committed_copies_of_central_files_fail_and_a_clean_repo_passes` and `::test_connector_standard_is_a_group_and_a_published_hook`. |
| `PIPE-VALIDATION-R001.8` | **Ignore-file defaults are shared.** `connector-codespell` runs codespell over tracked files outside tests and scripts with the shared default word list; extra words come from `[tool.pipelines.codespell] ignore_words` in `pyproject.toml`. Without codespell it fails closed in CI. | `tests/hooks/test_connector_central.py::test_codespell_defaults_are_shared_and_extended_from_pyproject`. |
| `PIPE-VALIDATION-R001.9` | **One reference connector configuration.** `templates/connector/pre-commit-config.yaml` is the whole connector pre-commit file: upstream hygiene and ruff hooks plus `connector-standard`, `secrets`, `spec` and `tests-fast` from this repository at `rev: main`, under 60 lines, naming only published hook ids and no copied sanitizer or bumpversion hook. | `tests/hooks/test_connector_central.py::test_reference_connector_config_names_only_published_hooks`. |
| `PIPE-VALIDATION-R001.10` | **The security scaffold is provided.** `pipelines-connector security {fuzz,authenticated-negative} OUT` writes the bounded fuzz and workflow control-plane evidence (privileged trigger, broad permissions, secret in shell, mutable action or container reference) that `.security/repository_fuzz.py` and `.security/authenticated_negative.py` copies wrote. `pipelines-connector security contract [--out PATH]` prints the effective contract: the packaged default hooks and license policy plus `[tool.pipelines.security] license_allowed / license_denied`; an unknown key or an allow/deny overlap is refused. The `connector-security` member of `connector-standard` runs both checks against the contract thresholds. A tracked `.security/security-contract.json` is a finding unless `scripts/security_contract.py` is tracked, because that validator still reads the file. | `tests/hooks/test_connector_security_scaffold.py::test_fuzz_and_negative_checks_write_the_evidence_the_contract_expects`, `::test_a_risky_workflow_is_a_finding_and_fails_the_check`, `::test_contract_is_the_shared_default_plus_pyproject_license_additions`, `::test_contract_refuses_unknown_keys_and_an_allow_deny_overlap` and `::test_committed_security_files_are_findings_unless_a_legacy_validator_reads_the_contract`. |
| `PIPE-VALIDATION-R001.11` | **`scripts/bootstrap.sh` is not provided.** A tracked `scripts/bootstrap.sh` is a finding naming its replacement: `uv sync --locked` installs the pinned Python from `.python-version` and the locked environment, and `uvx pre-commit install --hook-type pre-commit --hook-type pre-push` installs the hooks. No pipelines script replaces it. | `tests/hooks/test_connector_security_scaffold.py::test_committed_bootstrap_script_is_a_finding_that_names_what_replaces_it`. |
| `PIPE-VALIDATION-R001.12` | **API-to-MCP parity is a shared check.** The `connector-api-parity` member of `connector-standard` (also `pipelines-connector api-parity`) measures the share of public `api_client*.py` methods that an MCP tool in `mcp_server.py` or its sibling `mcp/*.py` calls through `client`, `api` or `self`, including a `resolve_action(.., <NAME>_ACTIONS)` catalog dispatched with `getattr`. A tool is a `.tool`-decorated function or one named with a `[tool.pipelines.api_integration] tool_prefixes` prefix. Coverage below `baseline` (default 0.0) fails; coverage below 100 always lists the unmapped methods. A repository without a client or a server passes; an unknown key or an invalid value is refused. | `tests/hooks/test_connector_security_scaffold.py::test_parity_counts_decorated_tools_and_catalog_dispatch_and_prefixed_tools_only_when_configured`, `::test_parity_fails_below_the_pyproject_baseline_and_lists_unmapped_methods`, `::test_parity_passes_without_a_client_or_server_and_refuses_bad_configuration` and `::test_a_committed_parity_script_is_a_finding_and_standard_runs_every_member`. |

| `PIPE-VALIDATION-R002` | **Privacy identity provenance.** Match Git-display-name-only candidates in identity fields or explicit attribution. Account, host, home-path, email, explicit override and prohibited-catalog identities remain strict everywhere. Independent strict provenance wins when sources overlap. No product-name allowlist applies. A bare personal name outside attribution can pass when Git display name is its sole source. | `tests/hooks/test_privacy_provenance.py` exercises the real CLI, contextual attribution, independent sources, same-line leaks and catalog precedence. Existing catalog refusal tests remain required. |
