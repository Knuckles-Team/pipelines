# PIPE-IDENTITY requirements

| ID | Requirement | Verification |
|---|---|---|
| `PIPE-IDENTITY-R001` | **Commit author identity is restricted to an allowlist (rollup).** pipelines enforces an author-identity allowlist in its pre-commit, pre-push, and CI checks, rejecting any commit whose author or committer name and email pair does not match one of a configured set of permitted identities. Children `.1` to `.7` deliver it. | Satisfied only when `.1` to `.7` are verified. |
| `PIPE-IDENTITY-R001.1` | **The delivery platform acts under one configured identity, and that identity gets no exemption.** The autonomous delivery platform must commit under one configured identity: either the owner's account or a dedicated service or bot account. The identity is one `{name, email}` entry of the allowlist, so the choice is a configuration change and not a code change. Whichever identity the platform uses, the owner's approval on the head commit gates every merge (`MEDULLA-SDLC-R019.10`, `ARBORA-OPS-R896.10`), and every gate stays required (`PIPE-GATES-R016.116.2`). Neither identity gate may branch on which allowlisted identity committed. An identity absent from the allowlist is refused, whether it is the owner's account or a service account. Refusal: the check names only the failing field. Knob: the allowlist entry set, read through `PIPE-IDENTITY-R001.2`; no other knob exists. Depends-on: PIPE-IDENTITY-R001.2, PIPE-GATES-R016.116.2. Caller chain: the same `secrets` group runs `commit-identity-range` when `PRE_COMMIT_FROM_REF` is set (`RANGE_MEMBERS`, `pipelines_hooks/cli.py:90`); `main` in `pipelines_hooks/identity/range_gate.py:37` reads the range with `range_identities` (`pipelines_hooks/identity/resolve.py:45`); the gates workflow exports `PRE_COMMIT_FROM_REF` for a pull request at `.github/workflows/gates_pipeline.yml:398`; the same allowlist match (`matches`, `pipelines_hooks/identity/allowlist.py:81`) judges every identity. Shape: no production code changes; `matches` and `resolved_allowlist` (`pipelines_hooks/identity/allowlist.py:81` and `:101`) already treat every entry alike, and the added tests in `tests/hooks/test_identity_range.py` reuse `write_identity_allowlist` and `commit_as` from `tests/hooks/conftest.py` with a synthetic service identity. | Tests: `tests/hooks/test_identity_range.py::test_a_service_identity_on_the_allowlist_is_checked_like_the_owner` and `::test_a_service_identity_off_the_allowlist_is_refused_in_ci` (planned). |
| `PIPE-IDENTITY-R001.2` | **Configured allowlist.** The gates must read a versioned, bounded allowlist of `{name, email}` pairs with no wildcard and no pattern. An empty, oversized or schema-invalid file is rejected before any commit is checked. The path resolves in this order: the `--allowlist` argument, `COMMIT_IDENTITY_ALLOWLIST`, a tracked `.config/commit-identity-allowlist.json`, then the packaged fleet default. Caller chain: the commit gate and the range gate both call `resolved_allowlist` (`pipelines_hooks/identity/allowlist.py:101`), which calls `configured_path` (`:86`) and `load_allowlist` (`:75`). Shape: `Identity`, `validated_terms` and `load_allowlist` in `pipelines_hooks/identity/allowlist.py`, the packaged `pipelines_hooks/identity/fleet-default-allowlist.json` declared as package data in `pyproject.toml`, and `pipelines_hooks/privacy/identity_catalog.py` as the precedent for the bounded loader. | Tests: `tests/hooks/test_identity_allowlist.py::test_p1_well_formed_allowlist_loads_and_validates`, `::test_n1_empty_or_schema_invalid_allowlist_is_rejected_before_any_commit_is_checked`, `::test_n1_oversized_allowlist_is_rejected` and `::test_configured_path_resolution_order`. |
| `PIPE-IDENTITY-R001.3` | **Commit-time enforcement.** At commit time the gate must read the author and committer identity git itself resolves for the commit being made and reject the commit when either pair is off the allowlist. The rejection names the failing field and prints no other configured identity. With nothing staged the gate passes. Caller chain: the hook `secrets` (`.config/pre-commit.yaml:53`, stages pre-commit and pre-push) runs `pipelines-hook secrets`, whose `main` (`pipelines_hooks/cli.py:151`) calls `run_group` (`pipelines_hooks/cli.py:121`); the group runs `commit-identity` through `run_gate` (`pipelines_hooks/cli.py:101`) and then `main` in `pipelines_hooks/identity/commit_gate.py:31`. Shape: `pending_identity` (`pipelines_hooks/identity/resolve.py:38`) reads `git var` through the sanitized helpers of `pipelines_hooks/core/gitenv.py`, and `_rejected_field` (`pipelines_hooks/identity/commit_gate.py:23`) picks the field to name. | Tests: `tests/hooks/test_identity_commit.py::test_p2_commit_time_accepts_an_allowlisted_author_and_committer`, `::test_n2_commit_time_rejects_an_identity_outside_the_allowlist_naming_only_the_field` and `::test_commit_time_with_nothing_staged_is_a_no_op_pass`. |
| `PIPE-IDENTITY-R001.4` | **Push-time and CI range enforcement.** Before a push, and again in CI, the gate must re-check every commit in the outgoing or incoming range, not only the branch tip, and refuse the push when one commit is off the allowlist. A pull request from a fork is an external contribution and is exempt; a push, a same-repository pull request and a local run are checked. An unreadable event payload counts as not exempt. Caller chain: the same `secrets` group runs `commit-identity-range` when `PRE_COMMIT_FROM_REF` is set (`RANGE_MEMBERS`, `pipelines_hooks/cli.py:90`); `main` in `pipelines_hooks/identity/range_gate.py:37` reads the range with `range_identities` (`pipelines_hooks/identity/resolve.py:45`); the gates workflow exports `PRE_COMMIT_FROM_REF` for a pull request at `.github/workflows/gates_pipeline.yml:398`; `is_fork_pull_request` (`pipelines_hooks/identity/fork_exemption.py:44`) is read first. Shape: `range_identities` (`pipelines_hooks/identity/resolve.py:45`), `_rejected_field` (`pipelines_hooks/identity/range_gate.py:29`) and `is_fork_pull_request`; the base revision comes from `upstream_base` (`pipelines_hooks/core/baseref.py:38`). | Tests: `tests/hooks/test_identity_range.py::test_p3_a_fully_matching_outgoing_range_succeeds`, `::test_n3_one_non_matching_commit_anywhere_in_range_is_refused_even_when_the_tip_matches`, `::test_n4_ci_reverification_rejects_a_range_even_when_the_local_check_was_bypassed` and `tests/hooks/test_identity_fork_exemption.py::test_fork_pull_request_is_exempt`. |
| `PIPE-IDENTITY-R001.5` | **Fail-closed diagnostics.** A missing explicit allowlist path is reported as `CANNOT RUN` and blocks in CI; locally it is a visible skip that names the install command. A malformed allowlist always exits 2. No default allowlist passes every identity. Caller chain: `run_gate` (`pipelines_hooks/cli.py:101`) calls the gate `main`; `resolved_allowlist` (`pipelines_hooks/identity/allowlist.py:101`) raises `Unavailable` or `CannotRun`, and `run_gate` maps them to a CI exit 2 or a local skip. Shape: `Unavailable` and `CannotRun` in `pipelines_hooks/core/errors.py` and the `REMEDY` text in `pipelines_hooks/identity/allowlist.py:31`; the `COMMIT_IDENTITY_ALLOWLIST` entry of `KNOWN_SETTINGS` in `pipelines_hooks/core/settings.py:24` is the one environment read. | Tests: `tests/hooks/test_identity_wiring.py::test_n5_an_explicitly_configured_missing_allowlist_fails_closed_in_ci`, `::test_n5_an_explicitly_configured_missing_allowlist_is_a_visible_local_skip_naming_the_remedy` and `::test_n5_a_malformed_allowlist_always_fails_regardless_of_ci`. |
| `PIPE-IDENTITY-R001.6` | **Wiring: both gates are published and run in the secrets group.** Both gate ids must resolve in the `GATES` table, and the `secrets` group must run them, so every consumer runs the identity check without extra setup. Caller chain: the `secrets` hook runs `run_group` (`pipelines_hooks/cli.py:121`) over `GROUPS["secrets"]` (`pipelines_hooks/cli.py:83`), which names `commit-identity` and `commit-identity-range`. Shape: two entries in `GATES` (`pipelines_hooks/cli.py:28` and `:29`) and the group tuple at `pipelines_hooks/cli.py:83`; no new file. | Test: `tests/hooks/test_identity_wiring.py::test_both_gates_are_registered_in_the_cli`. |
| `PIPE-IDENTITY-R001.7` | **Hot-path proof: the published command rejects an off-list identity.** The test must run the published command with a pending commit whose identity is off the allowlist and observe exit 1, then run the range command over a clean range and observe exit 0. Caller chain: the test enters at `main` in `pipelines_hooks/cli.py:151`, which runs `commit-identity` and `commit-identity-range` through `run_gate`. Shape: `tests/hooks/test_identity_wiring.py` uses the `repo` fixture of `tests/hooks/conftest.py` with `write_identity_allowlist` and `set_local_identity`. | Tests: `tests/hooks/test_identity_wiring.py::test_commit_identity_rejection_uses_the_published_cli_path` and `::test_commit_identity_range_is_invocable_through_the_cli_entrypoint`. |
