# PIPE-GATES requirements

| ID | Requirement | Acceptance |
|---|---|---|
| `PIPE-GATES-R001` | **Pre-land fast set and post-land full set.** The eight blocking gates partition into a pre-land fast set and a post-land full set. The fast set is `format`, `hygiene`, `secrets`, `types`, and `tests-fast`; it runs server-side against the changeset's tree in seconds and decides whether the changeset lands. The full set is the remaining blocking gates, `spec`, `tests`, and `supply-chain`; it runs after landing. Landing applies no merge queue. | The partition test asserts both sets' exact membership from the published gate configuration and asserts that the full set is the fast set's complement within the eight blocking gates. |
| `PIPE-GATES-R002` | **Auto-revert versus fix-forward.** A failed post-land gate triggers a recorded decision. The failure class decides it. The gate runner classifies each failure as `product` or `infrastructure`. An infrastructure failure means the gate produced no result, for example a lost runner. An unclassified failure is `product`. Auto-revert is the default; it reverts the failed changeset without operator action. Fix-forward applies only when the owner opens a fix-forward task within 300 s of the failed verdict. A passing re-run never changes the decision for a product failure. An infrastructure failure may re-run once. A passing re-run records `infrastructure-rerun`, and nothing reverts. The decision record carries the gate ID, the changeset ID, the verdict, the failure class, the threshold that fired, and the evidence digest. The record is replayable. | The policy test asserts the decision and the complete record for each failure class and threshold. A product failure whose re-run passes auto-reverts. |
| `PIPE-GATES-R003` | **Gates run against the engine tree.** Every blocking gate runs against the epistemic-graph tree without a local checkout. The gate reads file content by path and blob digest. Its verdict and evidence digest agree with the same gate run on a materialized checkout of the same revision. No working copy is required to land. | The contract test runs one blocking gate on an engine-tree fixture and on an identical materialized checkout and asserts that both runs produce the same verdict and evidence digest. |
| `PIPE-GATES-R004` | **Gate verdicts publish to the engine (rollup).** Each blocking gate run must publish its verdict as an EG-SCM-R008 record through the arbora `source.*` HTTP operations. The record binds gate id, input digest, verdict, evidence digest and duration. A publish failure never changes the verdict. Children `.1` and `.2` deliver it. | See each child. |
| `PIPE-GATES-R004.1` | **Wiring.** `run_gate_on` at `pipelines_hooks/gate_runner.py:62` calls `publish_verdict` in `pipelines_hooks/verdict_publish.py` after each gate. It uses plain HTTP and no ecosystem package. The arbora endpoint and token come from the CI environment. With no endpoint, the publish is skipped and logged. | `tests/test_verdict_publish.py::test_gate_run_posts_one_verdict` runs one gate against a fixture endpoint. |
| `PIPE-GATES-R004.2` | **Hot-path proof.** The test runs the fast gate set against a fixture tree with a fixture arbora endpoint. It observes one verdict record per gate with the tree digest. An endpoint error leaves every verdict unchanged. | `tests/test_verdict_publish.py::test_fast_set_publishes_and_survives_endpoint_error` asserts both cases. |
| `PIPE-GATES-R006` | **Changeset migration waves with entry and exit criteria (rollup).** Repositories move to engine changesets in seven ordered waves. A wave starts only when its entry criteria hold and the prior wave has exited. Each wave exits on its own criteria. GitHub stays a byte-identical mirror in every wave. Children `.1` to `.7` name the waves. | Satisfied only when `.1` to `.7` are verified. |
| `PIPE-GATES-R006.1` | **Wave 1: webarchiver.** Entry: EG-SCM-R001 to R004 and EG-SCM-R010 are verified. RM-SCM-R001 and RM-SCM-R002 are verified. ARBORA-OPS-R848.2 and ARBORA-OPS-R849 are verified. Exit: 20 changesets land through `source.land`. Each mirror commit has the tree hash of its changeset. One auto-revert rehearsal of PIPE-GATES-R002 passes. The mirror shows no divergence for 7 days. | `tests/hooks/test_migration_waves.py::test_wave_1_entry_and_exit` evaluates a fixture ledger and asserts each criterion. |
| `PIPE-GATES-R006.2` | **Wave 2: small connectors.** A small connector has under 10,000 source lines. Entry: wave 1 has exited. EG-SCM-R007 is verified. Exit: every small connector meets the wave 1 exit criteria for itself. | `test_wave_2_entry_and_exit` asserts the size bound and the per-repository exit. |
| `PIPE-GATES-R006.3` | **Wave 3: the remaining connectors.** Entry: wave 2 has exited. EG-SCM-R011 is verified. Exit: every connector meets the wave 1 exit criteria. Each connector release publishes from the mirror unchanged. | `test_wave_3_entry_and_exit` asserts the criteria. |
| `PIPE-GATES-R006.4` | **Wave 4: skills, pipelines and the user interfaces.** Entry: wave 3 has exited. PIPE-GATES-R003 is verified, so every blocking gate runs on the engine tree. Exit: universal-skills, pipelines, agent-webui, agent-terminal-ui and geniusbot meet the wave 1 exit criteria. | `test_wave_4_entry_and_exit` asserts the criteria. |
| `PIPE-GATES-R006.5` | **Wave 5: the SDK and the harness.** Entry: wave 4 has exited. SDK-SCM-R002 and AU-SCM-R001 are verified. Exit: agent-connector-sdk and agent-utilities meet the wave 1 exit criteria. | `test_wave_5_entry_and_exit` asserts the criteria. |
| `PIPE-GATES-R006.6` | **Wave 6: arbora.** Entry: wave 5 has exited. ARBORA-OPS-R850 and ARBORA-OPS-R851 are verified. Exit: arbora meets the wave 1 exit criteria. One release deploys from a changeset tree. | `test_wave_6_entry_and_exit` asserts the criteria. |
| `PIPE-GATES-R006.7` | **Wave 7: epistemic-graph, last.** Entry: wave 6 has exited. EG-SCM-R009 is verified. One restore of the engine source from the git mirror passes. Exit: epistemic-graph meets the wave 1 exit criteria. A second restore rehearsal passes. | `test_wave_7_entry_and_exit` asserts the criteria and the two restores. |
| `PIPE-GATES-R005` | **Spec text names no third-party product.** `pipelines-hook spec-standard` must refuse a third-party product or project name in authored `specs/**/*.md` text. Open standards and protocol names are never listed. | `tests/test_spec_third_party_names.py` asserts a finding for each named product, a pass for identifiers, code, links and standards, and the per-repository allowance. |

Explicit target repositories and worktrees are independent of ambient Git selectors, including the index. Findings fail with exit one; Git/read failures fail closed with exit two. This opt-in gate does not change the eight-gate landing partition. | Real Git fixtures cover detection, exclusions, tracked versus ignored/untracked files, foreign worktrees, polluted Git variables and CLI failure exits. |

| `PIPE-GATES-R010` | **Connector names agree with the declared fleet name.** Publish `connector-name` from pipelines. It reads the fleet name a connector declares as its single `agent_connector_sdk.connector` entry point in `pyproject.toml`. It compares that name with the `CONNECTOR` constant of each generated `connector_sources.py` (read by AST, never imported) and each `connector=` literal in a `ConnectorContent` or `IngestBinding` call. A disagreeing literal fails the gate and names the file. An undeclared connector with a literal gets a warning; `--strict` makes it a failure. A repository with neither passes. | `tests/hooks/test_connector_name.py` covers agreement, disagreement, the undeclared warning, `--strict`, a non-connector repository and that a leftover `connector_manifest.yml` is never read. |
| `PIPE-GATES-R011` | **Shared hooks are current and snapshots accept symlinks.** `gates_pipeline.yml` keys its pre-commit cache on the config hash and the current pipelines `main` commit. | `PIPE-GATES-R012` | **A connector that imports GraphQL declares it via the SDK extra.** Publish `connector-graphql` from pipelines. | `PIPE-GATES-R013` | **A connector uses the SDK capability instead of its own copy.** Publish `sdk-conformance` from pipelines. | `PIPE-GATES-R014` | **A connector ships and serves all five surfaces with a parent-linked ontology.** Publish `connector-surface-audit` from pipelines. It reads one connector checkout, or every repository of a fleet directory at a ref in detached worktrees, and prints one sorted JSON record per connector. Each record holds the `agent_connector_sdk.connector`, `skill_providers`, `prompt_providers` and `ontology_providers` entry points and any plugin group outside the SDK namespace. The parent classes come from the epistemic-graph parent ontology directory given with `--parent-ontology`. A record is complete when it has no gap. The audit reports by default; `--strict` exits 1 when any record is incomplete. The live surface and the engine pack contents are read by the arbora acceptance `surface_audit.py`, not by this audit. | `tests/hooks/test_connector_surface.py` builds fixture connectors and a fixture parent ontology in a temporary directory. | `PIPE-GATES-R015` | **Orphan connector classes get a reviewed parent class.** Publish `connector-ontology-map` from pipelines. `propose` reads each connector's ontology files at a git ref and the epistemic-graph parent ontology directory. For each orphan root class (the audit's reading of `orphan`) it scores candidate parent classes from an exact match of local name, label or alias, a head-noun match, a curated synonym table, a shared parent property, and a parent class named in the class comment. Each proposal carries its confidence and its reasons. Only an exact match is accepted unreviewed, and an exact match on a generic or BFO class is not. A class with no candidate is listed as a candidate for a new parent class. `decide` turns proposals and a reviewer's overrides into links and refuses an override that names a class the parent ontology lacks, so no parent class is invented. `apply` writes `rdfs:subClassOf` lines into the connector's Turtle text, and `owl:imports` of the parent IRI where the header lacks it, and changes nothing else in the file. `scaffold` writes the connector's `tests/test_ontology_parent_link.py`, which reads the ontology with the standard library only and asserts that the orphan classes are exactly the pending set. | `tests/hooks/test_ontology_orphan_map.py` builds a fixture parent ontology and connector ontologies in a temporary directory. | `PIPE-GATES-R016` | **The composed ontology graph is reachable and bridged.** Model: `connector-ontology-map graph-check` composes every epistemic-graph `*.ttl` at a ref (optionally overlaid with the ontology files an extra ref changed) and every fleet connector pack (`<pkg>/ontology/*.ttl`, shapes, and the generated `<pkg>/connector_sources.py`, whose `source_meta` entries, `SCHEMA_MAPPINGS` and `RESOURCES` are read statically by AST without importing the package) into one rdflib graph, with one module per EG file and one per pack. Behavior: it reports findings with the codes `PARSE_ERROR`, `ORPHAN_CLASS` (with chain length), `ISLAND_MODULE`, `ISLAND_PACK`, `DANGLING_REFERENCE` (file and line), `PROPERTY_UNTYPED`, `ISOLATED_CLASS` (data-only classes listed, not flagged), `UNBRIDGED_SAME_CONCEPT`, `INGEST_TYPE_MISSING`, `MAPPING_TARGET_MISSING`, `NO_JOIN_KEY`, `CONFLICTING_PARENT`, `DUPLICATE_LABEL` and `CQ_PATH_BROKEN`; it counts connected components of the module graph (reference edges and shared-IRI edges); it evaluates competency questions from a data file, each with the class and property hops it needs, and names every missing hop; and it groups the exact triples to add by owning repository (shared concepts in epistemic-graph, system-specific ones in the pack). Refusal: the exit code is 1 when any finding exists and 0 when clean; `--warn` always exits 0; an unparseable file is a finding and never aborts the run. Evidence: the JSON result (summary per code, pack and module, questions, fix plan, findings) and a Markdown report, deterministic with sorted keys and no timestamps. Hot-path: a read-only pass over `git show` output; no checkout and no network, about 25 seconds for the whole fleet. | `tests/hooks/test_ontology_graph_check.py` builds fixture graphs that exercise every code, the question evaluation with a missing hop, the owner grouping of the fix plan, determinism, the exit codes and the Markdown report, the static declaration read (never imported, a broken declaration is a `PARSE_ERROR`, a legacy manifest is ignored) and the command against a temporary git repository. |
