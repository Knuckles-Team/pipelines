| `PIPE-CONNSPEC-R001` | **Generated status with three hooks and four states.** The reference implementation lives in `pipelines_hooks/specs/`, exposing the hooks `spec-status`, `spec-decomposition`, and `spec-trailers`. Delivery status is generated, never hand-edited, and each requirement is in exactly one of the states SPECIFIED, LANDED, VERIFIED, or RETIRED. New landings use explicit Spec trailers or historical Spec subjects, never unrelated prose or none exemption reasons; historical receipts retain their existing validation. When specs exist, incomplete shallow Git history refuses generation and writes with exit 2 and a full-history fetch remedy, leaving status files unchanged; full history still rejects reverted or unreachable receipts. Repository ownership comes from origin or a sole configured remote, correcting stale checkout-derived owners without losing live legacy receipts; without an unambiguous remote identity, retain the old owner or finally the checkout name. A parent rolls up to the minimum state of its live children. A parent rolled up to LANDED carries its children's landing commits, and one rolled up to VERIFIED also carries their bound tests. During a resolved merge, default `spec-status` evaluates the index candidate tree with HEAD and MERGE_HEAD as parents and records evidence only from actual non-merge commits. An explicit `--head` remains authoritative even with unresolved conflicts. Default merge inference fails closed when conflicts remain or the worktree differs from its index. `spec-trailers` excludes commits already reachable from `origin/main` even when the pushed-over base is older, while continuing to validate all new branch commits against the current requirement and binding tree. Caller chain: the pre-push `spec` group (`pipelines_hooks/cli.py:84`) runs `main` in `pipelines_hooks/specs/status.py:110`, `decomposition.py:133` and `trailers.py:283`; `status.py` calls `generate` (`pipelines_hooks/specs/generator.py:116`), which reads Git history through `pipelines_hooks/specs/git_log.py`, bindings through `pipelines_hooks/specs/bindings.py:38` and identity through `pipelines_hooks/specs/repository_identity.py`. Shape: reuse `generate`, `render` and the `Row` parser in `pipelines_hooks/specs/requirements_doc.py`; the rollup and pending-merge logic stays in `generator.py` and `status.py`, and `status.json` stays an ignored output. | The files `pipelines_hooks/specs/status.py`, `decomposition.py`, and `trailers.py` exist; pending-merge tests in `tests/hooks/test_spec_status.py` verify candidate-tree history, explicit-head behavior, and fail-closed conflicts and index/worktree mismatch; `pipelines-hook spec-status --write` followed by `pipelines-hook spec-decomposition` runs clean in this repository. Test: `tests/hooks/test_spec_landing_attribution.py::test_github_squash_message_keeps_source_spec_trailers`, `tests/hooks/test_spec_landing_attribution.py::test_multiple_trailers_keep_ranges_and_shorthand`, `tests/hooks/test_spec_landing_attribution.py::test_pending_sibling_in_prose_does_not_land`. |
