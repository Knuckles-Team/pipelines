# PIPE-RELEASE requirements

| ID | Requirement | Verification |
|---|---|---|
| `PIPE-RELEASE-R001` | **Pipelines publishes images in dependency order with digest pins.** pipelines builds each repository's container image with an immutable digest pin, pushes repositories to GitHub in dependency order, and awaits hosted CI on each pushed revision before publishing the next stage, stopping before any downstream publication on failure. | Verified by an integration test with three ordered candidates confirming each stage's hosted CI must pass before the next stage publishes, per FR-3. |
| `PIPE-RELEASE-R002` | **Release tags point to the exact qualified commit.** pipelines verifies that a published GitHub release tag points to the exact source commit recorded in the qualified candidate manifest, rejecting any mismatch between the tag, the commit, and the published package artifact. | Verified by a negative test that a tag or artifact whose commit does not match the candidate manifest's recorded commit is rejected, per FR-1. |
| `PIPE-RELEASE-R003` | **Release build job sources environment values safely.** The release workflow's local build job writes and sources environment variables, including compiler flags such as CFLAGS, in a properly quoted form so a multi-token value is never misinterpreted as a shell command, and the build verifies byte-identical, reproducible wheels as part of its checks. | Verified by a build run whose steps complete via the real product build path rather than aborting early from an environment-sourcing error, and whose reproducibility check confirms byte-identical wheels across independent builds. |
| `PIPE-RELEASE-R004` | **Release gate fails when a compiled kernel wheel is missing.** Every published wheel set must hold one wheel with compiled numeric kernel binaries for each supported platform and Python version. The packaging gate must block publication when any combination is absent. | Run `test_missing_kernel_combination_blocks_release` in `tests/test_wheel_kernel_completeness.py`; expects exit 1 naming the missing combination. |
| `PIPE-RELEASE-R004.1` | **Model.** Add `KernelCell(target, python_tag, wheel)` and `KernelMatrix(required, found)` in new `.github/actions/wheel-readiness/kernels.py`. Existing `TARGETS` in `.github/actions/wheel-readiness/targets.py:7` lists four platforms. It has no Python version axis; line 30 pins 3.13. | Run `test_kernel_matrix_model_is_closed` in `tests/test_wheel_kernel_completeness.py` expects one cell per target and tag. |
| `PIPE-RELEASE-R004.2` | **Behavior.** Add `required_cells(targets, python_tags)` and `missing_cells(matrix)`. Each wheel counts only when its archive lists at least one compiled extension file (`.so`, `.pyd` or `.dylib`) matching its platform tag. The supported Python range is a named default, replaceable per publisher. | Run `test_wheel_without_binary_is_missing` in `tests/test_wheel_kernel_completeness.py` expects the pure-Python wheel to count as missing. |
| `PIPE-RELEASE-R004.3` | **Wiring.** Implementation is new `kernels.py`; no production caller today. Call `missing_cells` from `aggregate` at `.github/actions/wheel-readiness/bundle.py:98`, which `main` calls at `.github/actions/wheel-readiness/readiness.py:343` for the release publication step. | Run `test_aggregate_calls_kernel_gate` in `tests/test_wheel_kernel_completeness.py` expects `aggregate` to raise on a missing cell. |
| `PIPE-RELEASE-R004.4` | **Refusal.** `aggregate` must raise `KernelCellMissing` listing every absent `target/python_tag` pair. It must write no readiness receipt and must not publish. A repository that declares no compiled kernel must abstain with `no-kernel-declared`. | Run `test_missing_cell_refusal_lists_all_pairs` in `tests/test_wheel_kernel_completeness.py` expects every absent pair named. |
| `PIPE-RELEASE-R004.5` | **Evidence.** The aggregate receipt must carry a `kernel_cells` field with each required cell, its wheel file and its binary file names. A refused run must carry the missing pairs in the refusal message. | Run `test_receipt_records_kernel_cells` in `tests/test_wheel_kernel_completeness.py` expects `kernel_cells` equal to the required set. |
| `PIPE-RELEASE-R004.6` | **Hot-path proof.** The entry point is the `aggregate` run of `readiness.py` in the release bundle step, reached through `main` at `.github/actions/wheel-readiness/readiness.py:325`. A wheel directory missing one platform build must exit non-zero and write no receipt. | Run `test_release_bundle_blocks_missing_kernel_wheel` in `tests/test_wheel_kernel_completeness.py` expects non-zero exit and no receipt file. |
| `PIPE-RELEASE-R005` | **Dependency gate blocks circular dependency loops.** The dependency gate must detect loops among root, optional and development dependency groups. It must report each loop with its members and block landing until the loop is broken. | Run `test_dependency_loop_fails_gate` in `tests/hooks/test_dependency_cycles.py`; expects exit 1 naming the loop. |
| `PIPE-RELEASE-R005.1` | **Model.** Add `DependencyEdge(source_group, target_group, via)` and `DependencyLoop(members)` in new `pipelines_hooks/supply_chain/dependency_cycles.py`. Groups are `root`, each optional extra and each development group. Existing `declared_dependencies` at `pipelines_hooks/supply_chain/dependencies.py:32` flattens groups and loses edges. | Run `test_group_graph_model` in `tests/hooks/test_dependency_cycles.py` expects one node per group. |
| `PIPE-RELEASE-R005.2` | **Behavior.** Add `group_edges(document)` and `find_loops(edges)`. An edge comes from an `include-group` entry or from the project's own name with an extra. `find_loops` returns strongly connected components of size above one, plus self-loops, as `import_cycles.py:41` does. | Run `test_include_group_cycle_found` in `tests/hooks/test_dependency_cycles.py` expects a two-group loop reported. |
| `PIPE-RELEASE-R005.3` | **Wiring.** Implementation is new `dependency_cycles.py`; no production caller today. Call `loop_findings` from `dependency_findings` at `pipelines_hooks/supply_chain/dependencies.py:79` next to `_pyproject_findings`. `gate.py:71` calls `dependency_findings`; `supply-chain` is registered at `pipelines_hooks/cli.py:28`. | Run `test_dependency_findings_include_loops` in `tests/hooks/test_dependency_cycles.py` expects a loop finding. |
| `PIPE-RELEASE-R005.4` | **Refusal.** The gate must emit a finding with rule `SC-DEP-LOOP` per loop and exit 1. The finding must stay until the loop is broken. A manifest that fails to parse must give a typed parse finding, not an empty pass. | Run `test_unparseable_manifest_is_not_a_pass` in `tests/hooks/test_dependency_cycles.py` expects a parse finding. |
| `PIPE-RELEASE-R005.5` | **Evidence.** Each `SC-DEP-LOOP` finding message must list loop members in sorted order and the manifest path. The gate summary must count loops found. | Run `test_loop_finding_lists_sorted_members` in `tests/hooks/test_dependency_cycles.py` expects sorted members. |
| `PIPE-RELEASE-R005.6` | **Hot-path proof.** The entry point is `pipelines-hook supply-chain` through `main` in `pipelines_hooks/cli.py:79` on a fixture repository whose `pyproject.toml` has two groups including each other. The hook must exit 1 and print `SC-DEP-LOOP`. | Run `test_supply_chain_hook_blocks_dependency_loop` in `tests/hooks/test_dependency_cycles.py` expects exit 1 and the rule name. |
| `PIPE-RELEASE-R006` | **One bump configuration keeps project versions consistent.** Rollup of the children below. The gate checks metadata, source and documentation against one canonical project version. | The rollup is the minimum state of its children. |
| `PIPE-RELEASE-R006.1` | **Model.** Add `ProjectVersionInventory`, `VersionLocation` and `VersionCheck` in new `pipelines_hooks/release/project_version.py`. One canonical bump configuration owns current version and each location: repository-relative path, role (`metadata`, `source`, `documentation`), extraction selector, search/replacement templates and expected match count. Checks bind actual and expected values, line locations, configuration digest and Git snapshot. Every role requires at least one explicit location. | Run `test_project_version_inventory` in `tests/hooks/test_project_version_sync.py`. Accept a complete three-role inventory; reject unknown roles, duplicate locations and missing role coverage. |
| `PIPE-RELEASE-R006.2` | **Behavior.** The `exact-project-version` default compares every selected value with the canonical current version in the same Git snapshot. Parse metadata, literal source assignments and marked documentation text without imports or execution. Require selectors and bump templates to identify exactly the declared occurrences and preserve all other text. Validate template/extractor round trips; no implicit version normalization or whole-file version search is allowed. Historical release notes and dependency versions are outside the inventory unless explicitly declared. | Run `test_project_version_values` in `tests/hooks/test_project_version_sync.py`. Equal values pass; independently changing metadata, source, documentation or canonical current version fails at the exact location. |
| `PIPE-RELEASE-R006.3` | **Wiring.** Create `project-version-sync` in `GATES` at `pipelines_hooks/cli.py:13`, called by `run_gate` at `pipelines_hooks/cli.py:59`. Add its shared hook beside `.pre-commit-hooks.yaml:67`, catalogue and self-run configuration consumed by `.github/workflows/ci.yml:86`. Reuse snapshot selection at `pipelines_hooks/core/comparison.py:53` and blob reads at `pipelines_hooks/core/gitenv.py:81`. Inspect the full declared inventory in the index or selected committed tree, including the configuration; never mix worktree bytes. No production caller reaches this gate today. | Run `test_project_version_hook_wiring` in `tests/hooks/test_project_version_sync.py`. The installed CLI and published hook select the same snapshot and fail on an inconsistent unchanged declared surface. |
| `PIPE-RELEASE-R006.4` | **Refusal.** Return located `version-mismatch` findings and exit 1 for unequal extracted values. Raise `CannotRun` with a closed reason (`config-missing`, `config-invalid`, `config-ambiguous`, `inventory-incomplete`, `location-unreadable`, `selector-ambiguous`, `unsupported-extraction` or `snapshot-unavailable`) and exit 2 when any declared surface is unchecked. Reject missing or multiple matches, duplicate authorities, traversal, symlink entries and dynamic source expressions. Never skip an unreadable surface or repair files during checking. | Run `test_project_version_refusals` in `tests/hooks/test_project_version_sync.py`. Missing, malformed or competing configs and ambiguous extraction exit 2; mismatches exit 1 and cannot produce a passing receipt. |
| `PIPE-RELEASE-R006.5` | **Evidence.** Emit sorted role/path/line observations with expected and actual version, selector identity, checked count, configuration and blob digests, snapshot identity and typed refusals. A success record requires every location in every role to be checked. Record index-tree identity locally and commit/tree identity in CI. Print repository-relative locations only; do not publish unrelated source text or local machine paths. | Run `test_project_version_evidence` in `tests/hooks/test_project_version_sync.py`. Evidence identifies the exact checked Git bytes and all three roles; unchecked cases have no successful verdict. |
| `PIPE-RELEASE-R006.6` | **Hot-path proof.** Use entry point `pipelines-hook project-version-sync --root <fixture>` in `tests/hooks/test_project_version_sync.py` on a real temporary Git repository. Equal metadata, literal source and marked docs pass. Change and stage each surface independently: the published CLI and hook exit 1 at that line. Malformed, missing and ambiguous configs exit 2. An unstaged repair cannot hide an indexed mismatch; an unstaged mismatch cannot change a clean committed-tree result. Run the configured bump tool in the disposable fixture and prove it updates all three surfaces before the gate passes. | Run `test_project_version_sync_cli` in `tests/hooks/test_project_version_sync.py`. Assert real dispatcher/hook exit codes, exact locations, snapshot isolation, all-surface bumping and unchanged caller files during gate checks. |
