# PIPE-PAGES-001 requirements

| ID | Requirement | Verification |
|---|---|---|
| `PIPE-PAGES-R001` | **Repository switcher kept in sync with the core repo list.** The documentation site's repository switcher is renamed and its repository list is completed to match the full declared set of core repositories, replacing any per-repository duplicate copies and staying synchronized with the shared parity check and release receipt. agent-utilities' now-obsolete generator for a standalone web UI deployment manifest is also removed, since the web UI runs within Graph OS. | A parity check confirms the switcher's repository list matches the declared core-repository set and release receipt, and a source scan confirms the obsolete standalone deployment generator no longer exists. |
| `PIPE-PAGES-R002` | **Layered documentation from overview to reference.** The published documentation presents a layered information architecture: concise top-level introductions, then per-component overviews, then detailed reference pages, so a reader can go only as deep as they need. | A navigation-depth and link-structure audit confirms each tier, introduction, component, and reference, exists and links progressively into the next. |
| `PIPE-PAGES-R003` | **Present-tense docs with accessible embedded start.** The published README and documentation home present content in the intended canonical order, include an embedded observable quick-start demonstration, use accessible multimodal and shared visual assets, run on the shared Material-themed site with short navigation, and describe the running engine's current behavior in present tense rather than its history. | Strict documentation build, theme, accessibility, and content-diff checks confirm the README order, embedded start, shared visuals, and present-tense wording. |
| `PIPE-PAGES-R004` | **One progressively disclosed skill-graph corpus.** Concepts, components, and reference pages are drawn from one progressively disclosed skill-graph content corpus rather than separate, independently maintained sources. | A build check confirms the published concept, component, and reference pages are generated from the single skill-graph corpus with consistent navigation depth. |
| `PIPE-PAGES-R005` | **Generate architecture and reference pages from registries.** Architecture, capability, and reference documentation pages are generated directly from the underlying registries and contracts rather than hand-authored, so published content stays consistent with the implementation it describes. | A build-time comparison confirms each generated page's content matches its source registry or contract. |
| `PIPE-PAGES-R006` | **Rehome generated docs out of the legacy docs directory.** Every generated or gate-checked artifact currently stored under a repository's legacy docs directory is moved to its new canonical tracked location, every quality gate that referenced the old location is repointed to the new one, and the legacy docs directory is then removed. | A source scan confirms no gate or build step still reads from the removed docs directory and that each migrated artifact exists at its new tracked location. |
| `PIPE-PAGES-R007` | **Ecosystem flow diagram with exact names and project marks.** The documentation home page renders the shared Material theme chrome together with an architecture flow diagram showing the path from people through the Agent Web UI, Agent Terminal UI, Geniusbot, and messaging/protocol clients to Graph OS, agent-utilities, and the epistemic graph, plus the source-system-to-connector-SDK flow, using each project's exact display title and a versioned logo mark. | Focused theme rendering tests plus a changed-file documentation build confirm the diagram's flow, project titles, and logo marks render correctly. |
| `PIPE-PAGES-R008` | **Correct ownership and quick start in consumer parity checks.** The shared Pages parity check verifies that a consumer site's documentation correctly states process and front-door ownership, includes a stdio-based quick start, renders on the shared Material theme with short navigation, and keeps its content flows accessible. | A multi-page render, link, and accessibility audit plus a changed-file build check confirm ownership statements, the quick start, and accessible navigation on the consumer site. |
| `PIPE-PAGES-R009` | **HTML/CSS architecture views, no ASCII or Mermaid diagrams.** The shared Pages template renders architecture views as generated HTML/CSS graphics instead of ASCII art or Mermaid diagrams, so every consumer site displays consistent, accessible architecture diagrams from the one template. | A theme render check confirms architecture pages contain no ASCII-art or Mermaid diagram blocks and instead render the shared HTML/CSS view. |
| `PIPE-PAGES-R010` | **Generate API contract docs from the contract registry.** API contract documentation pages are generated from the canonical contract and method registry rather than hand-written, so the published reference stays synchronized with the registry's actual definitions. | A build-time comparison between the generated documentation pages and the source contract registry confirms they match. |
| `PIPE-PAGES-R011` | **Present-tense home page with screenshot and repo map.** The shared theme's documentation home page is present-tense HTML with short navigation, a real product screenshot, a map of the five core repositories, and a Graph-OS-hosted observable quick-start walkthrough. | Strict MkDocs render, accessibility, theme, and privacy gates, together with the documentation build run, confirm the home page's content and that it passes without regressions. |
